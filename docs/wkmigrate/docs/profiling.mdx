# Profiling and Assessment

Before migrating pipelines you can profile your Data Factory to understand its size and assess migration readiness. The profiler inspects every pipeline, activity, dataset, linked service, trigger, and integration runtime and reports which objects are supported by wkmigrate and which are not.

```python
from wkmigrate.clients.factory_client import FactoryClient
from wkmigrate.profiler import profile_factory, format_profile

client = FactoryClient(
    tenant_id="<YOUR AZURE TENANT ID>",
    client_id="<YOUR SERVICE PRINCIPAL CLIENT ID>",
    client_secret="<YOUR SERVICE PRINCIPAL CLIENT SECRET>",
    subscription_id="<YOUR AZURE SUBSCRIPTION ID>",
    resource_group_name="<RESOURCE GROUP WITH YOUR ADF INSTANCE>",
    factory_name="<YOUR ADF FACTORY NAME>",
)

# Profile the factory
profile = profile_factory(client)

# Print a human-readable summary
print(format_profile(profile))
```

The `FactoryProfile` returned by `profile_factory` contains counts for each object category (`pipelines`, `activities`, `datasets`, `linked_services`, `triggers`, and `integration_runtimes`), each broken down into `total`, `supported`, and `unsupported`. It also lists unsupported activity and dataset types, dataset details with linked service information, and integration runtime details.

<Admonition type="info" title="Programmatic access">
`FactoryProfile` is a dataclass so you can access counts directly (e.g. `profile.activities.unsupported`) and serialize it with `dataclasses.asdict(profile)` for JSON export.
</Admonition>
